# Vibe Coding 协作指南

## 1. 目标

本项目允许使用 AI 辅助进行快速探索和编码，但不能变成无约束的“边写边漂”。Vibe Coding 的目标是：

- 快速把想法落成可运行的最小实现。
- 保持项目方向、架构和文档同步。
- 降低 AI 误改、过度设计、遗漏安全约束的风险。
- 让每次会话结束后，项目仍然可接手、可验证、可继续。

## 2. 核心原则

### 2.1 TODO 是当前状态源

每次开始开发前先看：

```text
TODO.md
```

确认：

- 当前阶段
- 当前重点
- 下一步
- 阻塞事项
- 待确认问题

每次完成实际推进后，必须更新 `TODO.md`。

### 2.2 小步快跑

一次 AI 编码任务最好只做一个明确目标，例如：

- 初始化 Go module
- 实现 `/api/healthz`
- 添加 SQLite 初始化
- 创建 Dashboard 页面

避免一次性要求：

```text
把整个项目都写完
```

### 2.3 先立边界，再写代码

每次让 AI 做功能前，最好明确：

- 要改哪些文件
- 不要改哪些文件
- 验收标准是什么
- 是否需要同步文档
- 是否需要运行测试

示例：

```text
请只初始化 agent/ Go 项目，实现 /api/healthz，不要开始做 Windows Service 管理。
完成后更新 TODO.md，并说明如何运行验证。
```

### 2.4 文档和代码同步

如果代码改变了项目事实，必须同步文档。

典型例子：

| 代码变化 | 文档更新 |
|---|---|
| 新增 API | `docs/API.md` |
| 新增数据库表 | `docs/DATA_MODEL.md` |
| 改变安全策略 | `docs/SECURITY.md` |
| 改变架构边界 | `docs/ARCHITECTURE.md` |
| 改变开发流程 | `docs/WORKFLOW.md`, `AGENTS.md` |

### 2.5 可运行优先

优先保证：

- 可以启动
- 可以验证
- 可以回滚
- 可以继续开发

不要为了“看起来完整”一次生成大量未经验证的代码。

## 3. 推荐会话流程

### 3.1 开始会话

建议先让 AI 做上下文确认：

```text
请先阅读 AGENTS.md、TODO.md、README.md 和本次相关 docs，确认当前阶段和下一步，不要立即写代码。
```

### 3.2 制定小任务

让 AI 给出本轮最小任务：

```text
基于 TODO.md，列出本轮只完成一个最小任务的执行计划。
```

### 3.3 执行代码修改

执行时要求：

```text
按计划执行，只修改必要文件。完成后运行可行的验证命令，并更新 TODO.md。
```

### 3.4 结束会话

每次结束前要求 AI 汇报：

```text
请总结本轮修改、验证结果、TODO 更新情况、下一步建议。
```

## 4. 常用 Prompt 模板

### 4.1 开始新任务

```text
请阅读 AGENTS.md 和 TODO.md，选择当前下一步任务，先给出最小执行计划，不要直接写代码。
```

### 4.2 执行任务

```text
按刚才计划执行。要求：
1. 只修改本任务必要文件；
2. 如果影响 API/数据模型/安全/架构，同步更新 docs；
3. 完成后运行可行验证；
4. 更新 TODO.md。
```

### 4.3 代码审查

```text
请审查本轮改动是否符合 AGENTS.md、docs/SECURITY.md 和 docs/ARCHITECTURE.md。重点检查过度设计、安全问题、TODO 是否更新。
```

### 4.4 诊断问题

```text
请按“复现 → 最小化 → 假设 → 验证 → 修复 → 回归测试”的流程诊断，不要直接猜测修复。
```

### 4.5 文档同步

```text
请检查当前代码与 docs 是否一致，列出需要同步的文档，并完成必要更新。
```

## 5. AI 编码限制

除非用户明确要求，AI 不应：

- 一次性生成完整大系统。
- 绕过 `TODO.md` 直接选任务。
- 忽略安全文档实现高危能力。
- 默认开放远程访问。
- 直接删除用户文件。
- 把 token、密码、密钥写入代码或日志。
- 在没有验证的情况下宣称功能已完成。

## 6. 适合 Vibe Coding 的任务

适合：

- 项目骨架初始化
- API 原型
- UI 原型
- 配置模块
- 文档整理
- 小型重构
- 测试补充
- 错误处理完善

不适合一次性完成：

- Windows Service 全量管理
- 安装器完整链路
- 权限安全模型最终方案
- 跨平台抽象全量设计
- 远程管理能力

这些任务需要拆分为多个小任务逐步验证。

## 7. 最小完成定义

一个任务只有满足以下条件，才视为完成：

- 代码或文档已修改完成。
- 可行的验证命令已执行，或说明为什么暂时无法执行。
- 相关文档已同步。
- `TODO.md` 已更新。
- 最终回复说明修改内容、验证结果和下一步。
