# 产品需求文档 PRD

## 1. 背景

个人电脑上经常会运行多个后台服务或软件，例如数据库、代理工具、同步工具、本地开发服务、脚本任务、Docker 容器等。这些服务分散在 Windows Service、计划任务、注册表启动项、Startup 文件夹、普通进程等不同入口中，缺少一个统一、直观、可控的管理面板。

本项目希望提供一个本机部署的可视化面板，集中查看和管理个人电脑上的服务运行情况、开机自启状态，以及用户自定义添加的软件。

## 2. 产品目标

- 统一展示本机服务、进程、自启项和自定义软件。
- 支持启动、停止、重启、编辑、删除等基础管理操作。
- 可视化展示运行状态、PID、路径、启动类型、健康状态、最近错误。
- 允许用户添加自己想管理的软件或命令。
- 支持开机自启管理。
- 保持本地优先，不依赖云服务。
- 权限边界清晰，敏感操作由后台 Agent 执行。

## 3. 目标用户

- 个人开发者
- Windows 重度用户
- 本地部署软件使用者
- 需要管理多个后台工具的人
- 想要可视化管理开机启动项和系统服务的人

## 4. 核心场景

### 4.1 查看本机服务状态

用户打开面板后，可以看到：

- Windows 服务列表
- 自定义托管软件列表
- 当前运行状态
- 是否开机自启
- 异常服务数量

### 4.2 管理 Windows Service

用户可以对 Windows Service 执行：

- 启动
- 停止
- 重启
- 修改启动类型：自动、手动、禁用
- 查看可执行路径、服务名、显示名、描述

### 4.3 管理开机自启

用户可以统一查看：

- Windows Service 自动启动项
- 注册表 Run 启动项
- Startup 文件夹快捷方式
- 计划任务启动项
- 本工具托管的自定义自启程序

并可以启用或禁用部分自启项。

### 4.4 添加自定义软件

用户可以添加任意软件或脚本：

- 名称
- 可执行文件路径
- 工作目录
- 启动参数
- 停止命令，可选
- 是否开机自启
- 健康检查方式，可选

添加后可以从面板启动、停止、重启。

### 4.5 查看日志和异常

用户可以查看自定义软件日志：

- stdout
- stderr
- 最近日志
- 错误信息
- 健康检查失败原因

## 5. MVP 功能范围

MVP 只支持 Windows。

必须包含：

1. Go Agent 后台服务基础框架。
2. SQLite 配置存储。
3. React + Tauri 桌面面板基础界面。
4. Windows Service 列表展示。
5. Windows Service 启动、停止、重启。
6. Windows Service 启动类型查看和修改。
7. 自定义软件添加。
8. 自定义软件启动、停止。
9. 自定义软件是否开机自启配置。
10. 本机 API 安全 token。

暂不包含：

- 远程管理
- 云同步
- 多用户权限
- Docker 管理
- Linux/macOS 支持
- 插件系统

## 6. 非功能需求

### 6.1 安全

- API 仅监听 127.0.0.1。
- 请求需要本机 token。
- UI 不直接执行管理员操作。
- 敏感操作由 Agent 完成。
- 日志中避免输出 token、密码、密钥等敏感信息。

### 6.2 可靠性

- Agent 应作为 Windows Service 运行。
- UI 关闭不影响 Agent。
- Agent 重启后能恢复自定义软件状态信息。
- 操作失败需要有明确错误提示。

### 6.3 易用性

- 服务列表支持搜索和过滤。
- 危险操作需要确认。
- 添加服务向导尽量简单。
- 状态展示要清晰：运行中、已停止、异常、未知。

## 7. 成功标准

MVP 完成时应满足：

- 可以安装并启动 Agent。
- 可以打开桌面面板。
- 可以看到 Windows 服务列表。
- 可以启动/停止/重启指定服务。
- 可以添加一个 exe 程序并从面板启动/停止。
- 可以配置该程序开机自启。
- 配置重启后仍然保留。
