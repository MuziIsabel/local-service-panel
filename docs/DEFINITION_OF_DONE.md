# 完成标准 Definition of Done

## 1. 目标

本文件定义任务完成的最低标准，避免“代码写了但不可验证、文档没同步、TODO 没更新”的情况。

## 2. 通用完成标准

一个任务只有同时满足以下条件，才算完成：

- [ ] 实现或文档修改已经完成。
- [ ] 改动范围符合本轮目标，没有明显跑题。
- [ ] 可行的验证命令已执行，或说明无法执行的原因。
- [ ] 相关文档已同步。
- [ ] `TODO.md` 已更新。
- [ ] 如有明显推进，`TODO.md` 的进展日志已追加。
- [ ] 最终汇报包含修改内容、验证结果、风险和下一步。

## 3. 文档任务完成标准

文档类任务完成时应满足：

- [ ] 文档内容与当前项目决策一致。
- [ ] README 或相关入口已补充链接。
- [ ] 如果影响 AI/开发代理行为，`AGENTS.md` 已同步。
- [ ] `TODO.md` 已更新。

## 4. Agent API 任务完成标准

Agent API 相关任务完成时应满足：

- [ ] 路由已实现。
- [ ] 请求/响应格式符合 `docs/API.md`。
- [ ] 错误响应格式统一。
- [ ] 鉴权要求符合设计；healthz 可按设计例外。
- [ ] 已执行 `go test ./...` 或说明原因。
- [ ] 已执行本地启动验证或说明原因。
- [ ] 如 API 有变化，`docs/API.md` 已更新。

## 5. 数据库任务完成标准

数据库相关任务完成时应满足：

- [ ] schema 或 migration 已添加。
- [ ] 初始化逻辑可重复运行。
- [ ] 数据库路径可配置。
- [ ] 错误处理清晰。
- [ ] 如表结构变化，`docs/DATA_MODEL.md` 已更新。

## 6. 前端任务完成标准

前端任务完成时应满足：

- [ ] 页面或组件可渲染。
- [ ] TypeScript 类型合理。
- [ ] API 调用错误有用户可见反馈。
- [ ] 危险操作有确认。
- [ ] 已执行 `npm run lint` / `npm run build` 或说明原因。
- [ ] 如交互流程变化，相关文档已更新。

## 7. Windows Service 管理任务完成标准

Windows Service 管理相关任务完成时应满足：

- [ ] 不在 HTTP handler 中直接堆 Windows API 细节。
- [ ] 操作失败有明确错误返回。
- [ ] 对关键服务有保护或警告策略。
- [ ] 文档说明测试方式。
- [ ] 不使用关键系统服务做危险测试。
- [ ] 相关 API 文档已更新。

## 8. 自定义软件管理任务完成标准

Custom App 相关任务完成时应满足：

- [ ] 配置可持久化。
- [ ] 启动使用 executable path + args array。
- [ ] 不默认通过 shell 字符串执行。
- [ ] 工作目录和可执行路径有校验。
- [ ] stdout/stderr 处理策略明确。
- [ ] 停止逻辑有安全边界。
- [ ] 如涉及自启，`docs/SECURITY.md` 和 `docs/DATA_MODEL.md` 已同步。

## 9. 安全相关任务完成标准

安全相关任务完成时应满足：

- [ ] 默认不开放远程访问。
- [ ] token 不写入日志。
- [ ] CORS 不默认 `*`。
- [ ] 高危操作有确认或保护。
- [ ] 失败路径不会泄露敏感信息。
- [ ] `docs/SECURITY.md` 已同步。

## 10. 不能算完成的情况

以下情况不能算完成：

- 只写了代码但没有验证。
- 改了 API 但没更新 `docs/API.md`。
- 改了数据库但没更新 `docs/DATA_MODEL.md`。
- 改了安全策略但没更新 `docs/SECURITY.md`。
- 完成任务但没更新 `TODO.md`。
- 声称支持某功能但没有最小可运行路径。
- 引入大范围无关改动。
